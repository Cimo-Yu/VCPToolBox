【核心概念】VCPChat 有两个独立壁纸表面：聊天窗背景（三通路并存，全是"播放现成内容"）与桌面窗壁纸（wallpaperManager 三型）。AI 创作级动态壁纸的唯一落点：DesktopRemote SetWallpaper 推送 HTML → 沙箱 iframe 挂载 → 自动应用并持久化 layout.json。

【双仓插件结构】VCP 有两套插件体系：VCPToolBox/Plugin/（94 个 AI 工具端）+ VCPChat/VCPDistributedServer/Plugin/（32 个分布式端，经 WebSocket 与主进程通信）。DesktopRemote 属后者：desktop-remote.js 只是 stdin/stdout 校验管道（wallpaperSource 接受 source/url/content 等别名，规范化 JSON 输出），自身不执行任何桌面操作；真实逻辑在 VCPChat 主进程 modules/ipc/desktopRemoteHandlers.js 的 handleDesktopRemoteControl()。

【SetWallpaper 全链路（六步）】
1. AI 调用 → 管道规范化 → 2. _handleSetWallpaper(desktopRemoteHandlers.js:305) 三型分派：
- /^<!DOCTYPE|^<html/i → 落盘 PROJECT_ROOT/AppData/DesktopData/ai_wallpaper_<Date.now()>.html，source = 'file:///' + 正斜杠化路径，filePath 存原路径
- http(s):// → inferWallpaperType(URL pathname)
- file:// → inferWallpaperType(本地路径)
- 其它字符串 → 抛错（只收这三型）
三型 config 均置 enabled:true / opacity:1 / blur:0 / brightness:1。
→ 3. ensureDesktopWindow（桌面窗未开自动打开并等 2000ms，已开则 0）→ 4. webContents.send('desktop-remote-set-wallpaper', config) → 5. Desktopmodules/api/ipcBridge.js 接收：merge 进 state.globalSettings.wallpaper → window.VCPDesktop.wallpaper.apply() → 6. globalSettings.save() 持久化 layout.json，重启不丢。
推论：AI 每改一版推一次即自动应用+持久化，动态壁纸美术迭代成本 = 一次工具调用。

【已知边界不一致】desktopRemoteHandlers.inferWallpaperType 的 video 集 = ['mp4','webm']；wallpaperManager.detectType 的 video 集 = ['mp4','webm','ogg','mov']。经 SetWallpaper 推 .mov/.ogg 会被判 image 型（background-image 挂视频文件 → 黑屏）。用户手动选择的 dialog 过滤器也只放 mp4/webm。规避：AI 推送视频壁纸限定 mp4/webm；mov 仅 chat 侧辉宝插件支持。

【wallpaperManager 运行时（Desktopmodules/core/wallpaperManager.js）】#desktop-wallpaper-layer（z-index 0，body 与 canvas 之间）每次只挂一个元素（clear 时 innerHTML=''）→ 多层结构必须全部住在 HTML 壁纸 iframe 内部。三型：image=<div>+background-image / video=<video> autoplay·loop·muted·playsInline / html=<iframe>。html 型 iframe：sandbox="allow-scripts allow-same-origin" + allowTransparency + 强制 style.pointerEvents='none'（事件穿透桌面画布——壁纸拿不到任何鼠标事件，必须纯时间驱动的自治场景）。滤镜 opacity/blur/brightness 施加在整个壁纸层外层（用户领地，AI 不得依赖其数值）。detectType 按扩展名分派。切换动画：旧壁纸 0.4s 渐出 → HTML iframe load 后 1.2s 渐入（base.css .desktop-wallpaper-html.wallpaper-loaded）。

【CSP（desktop.html:6）】img-src * data: file: blob: / media-src * data: file: / frame-src 'self' file: data: / script-src 'self' 'unsafe-inline' / style-src 'self' 'unsafe-inline' https: / font-src * / connect-src * ws: wss:。→ HTML 壁纸 iframe 可直接 file:// 引用本地 PNG 素材，无需 base64。

【冻结协议（core/visibilityFreezer.js:158/183）】窗口遮挡/最小化时对壁纸 iframe postMessage({type:'vcp-freeze'}, '*') + iframe.style.visibility='hidden'（不是 display:none，故页面内 rAF 可能仍在跑）+ body 加 .desktop-frozen 全局暂停 CSS 动画；恢复时发 vcp-unfreeze 并复原。HTML 壁纸必须自实现该 postMessage 协议（监听 message 切换 .frozen{animation-play-state:paused}），否则被遮挡时持续耗 GPU。

【桌面窗口物理参数（modules/ipc/desktopHandlers.js）】置底 = Windows 原生 SetWindowPos(HWND_BOTTOM)（PowerShell 通道）每 1.5s 强制下沉 + 获焦 50ms 后下沉（非 Windows 平台用 setAlwaysOnTop 近似）；autoMaximize 启动即最大化，单窗口单显示器，画布 = 主屏全分辨率。

【chat 聊天窗背景 = 三通路并存】
1. themes.js：CSS 变量 --chat-wallpaper-dark/light → background-image:url() + cover，静态单图，走 get-wallpaper-thumbnail IPC 取缩略图。
2. 辉宝 VChatDynamicWallpaper：本地视频文件夹（mp4/webm/mov/mkv/avi），fixed + z-index:-1，胶片控制栏，与 VCPDesktop 壁纸系统相互独立。
3. VCPWEWallpaper(service) + VCPWEWallpaperUI(renderer)：Wallpaper Engine 库存桥接。service 经 5974 端口 Express 挂 inventory/media/preview 路由；UI 三形态按壁纸能力分派：web 型 iframe / video 型 / image 静态兜底；8s 未 load 判白屏降级 preview；与辉宝插件互斥（激活即改其内存态，不动 localStorage）；前置条件 = main.html CSP 放行 frame-src http://127.0.0.1:5974。
判定：三条全是"播放现成内容"通路，均无分层渲染能力；分层动画唯一落点在 desktop HTML 壁纸 iframe。

【MediaRenderer 批量导出真相（VCPToolBox/Plugin/MediaRenderer/MediaRenderer.js）】MAX_BATCH_SIZE = 16（:34）；MAX_DIMENSION = 4096，MAX_PIXELS = 4096×4096；MAX_SOURCE_BYTES = 2MB（源码）；MAX_SOURCE_IMAGE_BYTES = 25MB（单图素材）。collectSteps(:1571)：command1/html1/svg1… 编号参数按序收集，遇第一个缺口即 break，超 16 步抛"单次最多串行渲染 16 张图片"；每步独立 renderOne(browser, steps[index], index+1)，各自输出独立文件。
判定：其"多层"是导出侧批量（一次调用得 N 张独立透明 PNG），非运行期可寻址图层——每个输出永远压平，不保留层结构。分层运动必须由前端（HTML 壁纸 iframe）承担。

【未验证（刻意不入事实层）】生图模型能否直出透明底 PNG；沙箱 file:// iframe 内 script src=file:// 加载外部 JS 库是否被 Chromium 拦。
