# VCPdesktop 桌面窗物理参数与置底机制（源码实证）

## 核心概念
VCPdesktop 桌面窗是一个**普通不透明 BrowserWindow**，其"桌面感"完全由后处理（原生置底 + 无边框 + 自动最大化）合成，而非由窗口本身的特殊类型提供。这一判定决定了所有涉及指针、命中测试、图层的功能的实现难度。

## 窗口创建参数
`modules/ipc/desktopHandlers.js:2354` `openDesktopWindow()`：
```js
desktopWindow = new BrowserWindow({
    width: 1200, height: 800, minWidth: 600, minHeight: 400,
    title: 'VCPdesktop',
    frame: false,
    ...(process.platform === 'darwin' ? {} : { titleBarStyle: 'hidden' }),
    webPreferences: {
        preload: resolveAppPreload(app.getAppPath(), PRELOAD_ROLES.DESKTOP),
        contextIsolation: true,
        nodeIntegration: false,
    },
    icon: path.join(app.getAppPath(), 'assets', 'icon.png'),
    show: false,
});
```
**关键缺项**：无 `transparent`、无 `setIgnoreMouseEvents`、无 `hasShadow:false`、无 `type:'desktop'`。

加载 URL 带主题参数：`file://<appPath>/Desktopmodules/desktop.html?currentThemeMode=<dark|light>`；随后 `windowService.attachWindow(WINDOW_APP_IDS.DESKTOP, ...)` 与 `setMenu(null)`。

## 对照：真正的穿透窗
`modules/ipc/ragHandlers.js:201/363/427` 的 RAG overlay 才使用
`setIgnoreMouseEvents(passThrough, { forward: true })` + `setAlwaysOnTop(true,'screen-saver')` + `setVisibleOnAllWorkspaces(true,{visibleOnFullScreen:true})`。

**判据**：同一仓库内两类窗口对"指针相关功能"的实现成本差一个量级。凡涉及鼠标的改动，先判断目标是普通窗还是穿透窗，再判难度。桌面窗属前者，故一切光标/命中测试问题都是纯客户区 DOM 问题，不触 OS 层。

## 启动序列（ready-to-show）
`desktopHandlers.js:2396` 起：
1. `autoMaximize` 为真 → `desktopWindow.maximize()`
2. `showInactive()`（**不抢主窗口焦点**）
3. `alwaysOnBottom` 为真 → 500ms 后 `setAlwaysOnBottom(true)`
4. 向自身与主窗口各发 `desktop-status {connected:true}`（后者让 streamManager 知道可推送）

全局设置来源为 `LAYOUT_CONFIG_PATH` 指向的 layout.json 中的 `globalSettings` 段，读取失败时降级为 `{}`。

## 置底机制（alwaysOnBottom）
IPC 入口 `desktop-set-always-on-bottom`（`desktopHandlers.js:1017`），preload 侧暴露名 `setAlwaysOnBottom`，见 `preloads/desktop.js:419`、`preloads/utility.js:464`、`preloads/chat.js:453`、`preloads/shared/catalog.js:344`，白名单在 `preloads/shared/roles.js:215` 与 `preloads/desktop.js:478`。

实现（`desktopHandlers.js:2587` `setAlwaysOnBottom(enabled)`）：
- **Windows**：`getNativeWindowHandle().readInt32LE(0)` 取 hwnd → `startBottomHelper(hwnd)` 启动**持久化 PowerShell 子进程**，通过 stdin 写 `[VCPWinAPI]::PushToBottom([IntPtr]<hwnd>)` 调用 Win32 `SetWindowPos(HWND_BOTTOM)`。
- **非 Windows**：`setAlwaysOnTop(true,'screen-saver',-1)` 紧接 `setAlwaysOnTop(false)` 作为近似。

三条触发路径并存：
1. `desktopWindow.on('focus')` → 50ms 后 `pushToBottom()`（获焦即沉）
2. `setInterval(pushToBottom, 1500)`（`:2643`，周期强制下沉）
3. 启用后 200ms 的初始下沉（等 PowerShell 进程就绪）

清理：`desktopWindow.on('closed')` 中置 `alwaysOnBottomEnabled=false`、`clearInterval`、`stopBottomHelper()`；所有 setTimeout 均以 `desktopWindow.once('closed', ...)` 配对 clearTimeout。

**副作用（重要）**：置底模式下窗口每 1.5s 经历一次"可能夺焦 → 强制下沉"，且获焦即沉。故 **`window.blur` 在置底模式下是高频常态事件，不能作为"用户离开窗口"的判据**。任何以 blur 为触发条件的渲染层逻辑（隐藏自绘光标、暂停动画、收起面板）都会以约 1.5s 的节奏抖动。正确判据应改为指针是否在客户区（`mouseenter`/`mouseleave`）。

## 标题栏与拖拽区
`Desktopmodules/css/base.css:96-104`：`#desktop-title-bar { position:fixed; top:0; height:32px; z-index:9999; -webkit-app-region:drag; opacity:0.15 }`，`:hover` 时 opacity 升至 1。按钮组 `.desktop-title-buttons { -webkit-app-region:no-drag }`。

`webkitAppRegion` **是运行期可变属性**：`Desktopmodules/ui/globalSettings.js:318-341` 在"锁定最大化"开关下用 JS 在 `'drag'` 与 `''` 之间切换 titleBar 与 dragRegion 的该属性，同时禁用最大化按钮（`disabled=true`、`opacity=0.3`、`cursor='not-allowed'`）。
